# 功能规格说明：用户管理后端服务

**功能分支**：`001-user-management`

**创建日期**：2026-05-26

**最后更新**：2026-05-26

**状态**：草稿

**输入**：用户描述：Spring Boot 2.7.18 + JDK 1.8 后端项目；基础框架 Spring Boot + Spring MVC + MyBatis + MyBatis Plus；用户管理（增删改查、分页、条件查询）；RESTful API + Swagger；统一返回 code/msg/data；全局异常捕获、参数校验、Swagger 接口文档；application.yml 多环境（dev/test/uat/pre/prod）；logback 文件日志。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 创建并查看用户（优先级：P1）

作为系统管理员或集成方，我需要能够新增用户并查看单个用户详情，以便完成最基础的用户主数据维护。

**优先级理由**：创建与按标识查询是用户管理的 MVP，无此能力则无法进行任何后续维护。

**独立测试**：仅实现本故事时，可通过「创建用户 → 按 ID 查询」完整验证，并交付可用的最小用户主数据能力。

**验收场景**：

1. **假如** 提供合法的用户信息，**当** 提交创建请求，**那么** 系统返回成功及新用户的唯一标识，且后续可按该标识查询到一致信息
2. **假如** 用户标识存在，**当** 查询该用户，**那么** 返回该用户的完整业务字段（不含敏感凭证明文）
3. **假如** 用户标识不存在，**当** 查询该用户，**那么** 返回明确的「未找到」类错误信息，且统一响应格式中 code 表示失败
4. **假如** 提交重复的唯一业务键（如用户名或邮箱），**当** 创建用户，**那么** 拒绝创建并返回可理解的冲突说明

---

### 用户故事 2 - 分页浏览与条件查询用户（优先级：P2）

作为系统管理员，我需要按页浏览用户列表，并按条件筛选，以便在大量用户中快速定位目标记录。

**优先级理由**：列表与检索是日常运维的高频操作，依赖 P1 已有持久化数据。

**独立测试**：在已有若干用户数据的前提下，仅实现本故事时，可独立验证分页及多条件组合查询结果是否正确。

**验收场景**：

1. **假如** 存在多条用户记录，**当** 请求第 N 页且每页 M 条，**那么** 返回当前页数据、总条数及分页元信息，且不超过 M 条
2. **假如** 指定用户名关键字（模糊）或状态等条件，**当** 查询列表，**那么** 仅返回满足条件的用户
3. **假如** 页码或每页条数非法（如为 0 或超过上限），**当** 请求列表，**那么** 返回参数校验失败说明，不返回未处理的系统错误
4. **假如** 无匹配记录，**当** 条件查询，**那么** 返回空列表及总条数 0，仍视为成功响应

---

### 用户故事 3 - 更新与删除用户（优先级：P3）

作为系统管理员，我需要修改用户信息并删除（或停用）用户，以保持主数据准确、及时。

**优先级理由**：完整生命周期管理依赖已有创建与查询能力，可在 P1、P2 之后交付。

**独立测试**：在已有用户数据下，可单独验证更新字段生效、删除后按约定不再作为有效用户展示。

**验收场景**：

1. **假如** 用户存在且提交合法更新字段，**当** 更新用户，**那么** 再次查询时展示更新后的值，且自动记录更新时间
2. **假如** 更新导致唯一键与其他用户冲突，**当** 提交更新，**那么** 拒绝更新并返回冲突说明
3. **假如** 用户存在，**当** 执行删除（或停用），**那么** 不再作为「有效用户」出现在默认列表与详情中
4. **假如** 用户不存在，**当** 更新或删除，**那么** 返回明确的未找到错误，不产生静默失败

### 边界情况

- 必填字段缺失或格式错误（邮箱、手机号等）时，返回字段级校验提示，不写入数据库
- 分页参数边界：超大页码、超大 pageSize 需限制上限并友好提示
- 并发创建相同唯一键时的冲突处理
- 逻辑删除后，允许使用相同用户名/邮箱创建新用户（原记录已失效）
- 服务异常时，调用方始终收到统一结构响应（code、msg、data）

## 需求 *（必填）*

### 功能需求

- **FR-001**：系统 **必须** 支持创建用户，至少包含：用户名、登录密码（存储为不可逆摘要，响应中不得返回明文）、邮箱、手机号、状态（启用/停用）
- **FR-002**：系统 **必须** 支持按用户唯一标识查询单个用户详情
- **FR-003**：系统 **必须** 支持分页查询用户列表，并返回总条数及当前页数据
- **FR-004**：系统 **必须** 支持按组合条件筛选列表（默认：用户名模糊匹配、状态精确匹配；可扩展邮箱、手机号）
- **FR-005**：系统 **必须** 支持更新用户可编辑字段（用户名、邮箱、手机号、状态、密码可选更新）
- **FR-006**：系统 **必须** 支持删除用户；默认采用**逻辑删除**，不在默认列表与详情中展示
- **FR-007**：所有对外 HTTP 接口 **必须** 遵循 RESTful 风格（资源路径、合适 HTTP 方法、合理状态码语义）
- **FR-008**：所有接口响应 **必须** 使用统一包装：`code`（业务/结果码）、`msg`（说明）、`data`（业务数据，失败时可为空）
- **FR-009**：系统 **必须** 对可预期异常（参数错误、未找到、冲突、校验失败等）进行统一捕获并转换为 FR-008 格式
- **FR-010**：系统 **必须** 对入参进行校验，并在校验失败时返回可定位到字段的错误信息
- **FR-011**：系统 **必须** 提供 Swagger 在线接口文档，覆盖全部对外 REST 接口及主要请求/响应说明
- **FR-012**：系统 **必须** 支持 **dev、test、uat、pre、prod** 五套运行配置，通过激活环境切换，无需修改代码
- **FR-013**：系统 **必须** 使用 Logback 将运行日志输出到文件，并支持按环境配置日志级别与路径

### 关键实体

- **用户（User）**：系统被管理的主体。关键属性：唯一标识、用户名（唯一）、密码摘要、邮箱（唯一）、手机号、状态、创建时间、更新时间、删除/停用标记。用户名与邮箱在有效用户范围内唯一。

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**：管理员可在 5 分钟内通过 Swagger 文档完成「创建 → 查询 → 更新 → 列表筛选 → 删除/停用」全流程，无需阅读源代码
- **SC-002**：在 1 万条用户数据量下，分页列表在常规部署下 95% 请求可在 2 秒内返回
- **SC-003**：100% 的非法入参请求返回统一格式错误响应，且 msg 能说明失败原因类别
- **SC-004**：Swagger 文档中的端点与实际上线端点一致率 100%
- **SC-005**：在 dev、test、uat、pre、prod 各环境配置下，应用均可正常启动，且日志写入对应环境的日志文件

## 假设

- 本功能为**新建后端服务**的首个业务能力，无遗留用户数据迁移
- v1 **不包含** 登录认证、角色权限、操作审计；接口面向受信任内网或后续由网关鉴权
- 用户密码在服务端以单向摘要存储；HTTPS 由部署环境负责
- 删除策略默认为**逻辑删除**
- 列表默认按创建时间倒序；默认每页 10 条，最大每页 100 条
- 持久化访问层采用 **MyBatis + MyBatis Plus**（非 JPA）；Web 层采用 **Spring MVC**
- 技术实施须符合 `.specify/memory/constitution.md`：JDK 1.8、Spring Boot 2.7.18、Maven、UTF-8、MySQL 8.0、Controller/Service/Repository/Entity 分层、Logback、阿里巴巴 Java 开发手册；接口文档以 **Swagger** 为准（若与宪法 knife4j 表述冲突，以本功能规格及计划阶段选型为准）
